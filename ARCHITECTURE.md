# Архитектурные инструменты 0.3.0

Форк: https://github.com/igorderp/rnpmcp. Исходный проект: https://github.com/proovcme/rnpmcp.

## Что добавлено

Сервер предоставляет 25 инструментов: исходные 14 и 11 новых. Дополнения предназначены для сверки существующего здания с чертежами, расстановки окон и дверей, исправления базовых линий стен, построения лестниц и площадок.

`renga_get_geometry` возвращает положение объекта, единицы `mm`, родительский уровень и его отметку, вертикальное смещение, базовую линию/контур, точные концы сегментов и зависимые ID. `Unavailable` явно перечисляет неподдерживаемые интерфейсы. Равномерные отсчёты кривых не являются точными границами или доказательством отсутствия коллизий. Для поликривых дополнительно возвращаются сегменты; для прямых их концы точны.

`renga_create_object_at` создаёт объект с размещением, локальной базовой линией и параметрами в одной операции. Добавлен тип `Stair`. Площадки создаются как `Floor` с замкнутым контуром, окна/двери — с явным хостом `Wall`. Стиль выбирается через существующий `renga_list_styles`.

`renga_set_placement`, `renga_set_baseline` и `renga_set_parameters` исправляют существующие объекты. Положение и базовая линия хоста с зависимыми объектами не меняются: Renga ограничивает такие операции. Окна/двери нельзя переносить через `ILevelObject.SetPlacement`; их замена должна быть отдельным явно разрешённым действием.

`renga_delete_objects` сначала показывает весь фактический каскад удаления в preview. Для commit обязателен `expectedDeletedUniqueIds` с тем же полным набором GUID. Любое несовпадение откатывает операцию. GUID из preview вновь созданного объекта не существует после отката.

`renga_get_selection`, `renga_select_objects`, `renga_get_view` и `renga_open_view` позволяют выбрать объекты и открыть 3D-вид или план уровня. Эти команды меняют только интерфейс. Пустой список выбора снимает выделение.

`renga_get_screenshot` возвращает MCP image content (`image/png`) непосредственно через `IScreenshotService`. Не зависит от Windows Graphics Capture и не пишет файлы. Размер ограничен 64–4096 px по каждой стороне, 8 млн пикселей и 10 MiB данных. Нужен активный модельный вид; в mock-режиме рендера нет. Снимок показывает только область модели, не панели, диалоги или карту экранных координат для кликов.

## Координаты и единицы

- Координаты и размеры геометрии — миллиметры. Оси — перпендикулярные единичные векторы; ось Y определяется как Z × X.
- `create_object_at.placement` задаётся в системе проекта. Renga может проецировать зависимый объект на хост; фактическое положение нужно читать из результата.
- На проверенной API 2.49 Renga привязывает Z нового объекта к заданному уровню. Сервер компенсирует разницу через `Offset`, чтобы сохранить заданную глобальную отметку. Явные пользовательские `parameters` применяются после этой компенсации и могут её переопределить.
- `set_placement.placement` задаётся в системе родительского уровня, в той же системе, что `get_geometry.placement`.
- Базовая линия и контур задаются в **локальной XY-системе объекта**, не в системе проекта. Преобразуйте точки с учётом размещения объекта и уровня.
- Для замкнутого контура не повторяйте первую вершину. Проверяются конечность координат, число вершин, нулевые рёбра, самопересечения и ненулевая площадь. Поддерживаются 2–256 вершин, для замкнутого контура — от 3.
- ID параметров берутся из `renga_get_object`. Значения строковые в invariant-формате: `false`, `6`, `1510`, `0.05`. Единицы параметров определяются API, а не локализованным названием.

## Транзакции и проверка

Новые инструменты изменения модели используют `preview=true` по умолчанию. Перед записью проверяется отсутствие активной операции. Все изменения одной команды выполняются в одной операции с undo; если GUID модели не удаётся прочитать через нативную сигнатуру, новые инструменты отказываются от записи вместо перехода к операции без undo. Ошибки валидации и COM до Apply приводят к Rollback.

Часть значений параметров Renga вычисляет при Apply. Чтение через прежний объект `IParameter` до Apply может вернуть старое значение, а для нового объекта — ошибку COM. Поэтому preview проверяет возможность вызова setters и откатывается, но не заявляет подтверждение окончательных значений. Результат содержит `RequestedParameters` и `ParameterReadbackRequired`. После commit прочитайте `renga_get_object`, проверьте размеры и сделайте снимок. Геометрия после commit перечитывается через свежие COM-объекты. Успешный API-вызов сам по себе не подтверждает проектное качество или соответствие нормам.

Не сохраняет, не синхронизирует и не закрывает проект. Установка обновлённого MCP также не требует закрывать Renga.

## Проверка на живой Renga

Проверено на Renga Professional 9.2 / API 2.49:

- чтение размещений, отметок, базовых линий стен и сегментов поликривых;
- выбор/снятие выбора, открытие 3D-вида и PNG модельного вида;
- preview перемещения и изменения базовой линии существующей стены с проверкой восстановления;
- preview создания стены, окна, перекрытия с четырьмя рёбрами и лестницы;
- preview удаления стены с получением также удаляемых соединений;
- сохранение исходного набора объектов после всех preview;
- discovery 25 MCP-инструментов, JSON-схемы структурированных аргументов и image content через настоящий stdio JSON-RPC.

Commit новых геометрических инструментов на пользовательском проекте в ходе этой проверки не выполнялся. Mock-тесты проверяют сохранение состояния при preview, изменение состояния при commit и отказ удаления при несовпадении ожидаемого набора. Реальный commit необходимо дополнительно проверять повторным чтением и визуально.

## Техническая реализация

`GeometryCom` использует оригинальные короткие объявления сигнатур и структур из публичной документации. IID интерфейса и смещение метода разрешаются по типовой библиотеке установленной Renga; чужие бинарные файлы, Interop-сборки, TLB и SDK в форк не добавляются. Для освобождения COM используется один `ReleaseComObject` на приобретённую ссылку: `FinalReleaseComObject` мог разорвать ещё используемый RCW при вложенном получении одного объекта или `ITypeInfo`.

Официальные контракты: [ILevelObject](https://help.rengabim.com/api/interface_i_level_object.html), [IBaseline2DObject](https://help.rengabim.com/api/interface_i_baseline2_d_object.html), [INewEntityArgs](https://help.rengabim.com/api/interface_i_new_entity_args.html), [IMath](https://help.rengabim.com/api/interface_i_math.html), [IScreenshotService](https://help.rengabim.com/api/interface_i_screenshot_service.html), [ISelection](https://help.rengabim.com/api/interface_i_selection.html).
