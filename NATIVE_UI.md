# Нативное копирование, уровни и перемещение — 0.4.0

В сервере 31 инструмент: 25 прежних и 6 новых. Новые UI-команды работают только с окном **подключённого процесса Renga**. Они не принимают произвольные HWND, команды оболочки или сочетания клавиш.

## Что изменилось

| Инструмент | Назначение |
| --- | --- |
| `renga_get_levels` | Все уровни, их GUID, имена, точные отметки в миллиметрах, размещение и доступность записи отметки через API |
| `renga_move_objects` | Пакетный сдвиг объектов на вектор X/Y/Z в одной операции с undo; preview выполняет операцию и откатывает её |
| `renga_ui_snapshot` | PNG клиентской области окна с панелями или текущим диалогом и точными координатами для UI-ввода |
| `renga_ui_key` | Штатные Copy/Paste/Create copy/Move, Enter/Esc/Tab и ограниченный набор клавиш навигации |
| `renga_ui_click` | Щелчок, двойной щелчок, Ctrl/Alt/Shift+щелчок по координатам свежего UI-снимка |
| `renga_ui_type_text` | Ввод Unicode в наблюдаемое поле Renga без использования буфера обмена |

`renga_get_geometry` для самого уровня дополнительно возвращает `ownLevel`, включая его собственную отметку и размещение. Поле `levelElevation` по-прежнему означает отметку **родительского** уровня объекта.

## Два разных режима проверки

API-команда `renga_move_objects` по умолчанию реально выполняется в транзакции и откатывается. Для сохранения сдвига необходимо явно указать `preview=false`. При ошибке любого объекта откатывается весь набор. Запрещены закреплённые объекты и хосты с зависимостями; SetPlacement некоторых типов Renga не поддерживает. Сервер проверяет фактический сдвиг и не считает проигнорированный setter успешным.

У UI-команд `preview=true` означает **только проверку и план без отправки ввода**. У клавиатуры и мыши нет транзакционного rollback. `preview=false` выполняет один ввод, потребляет токен снимка и возвращает следующий снимок. Отправленная клавиша ещё не означает завершённую операцию над моделью. Ни один новый инструмент не сохраняет и не закрывает проект автоматически.

## Общий порядок UI-действий

1. Подключиться через `renga_connect`. Прочитать объекты/уровни и запомнить исходное состояние.
2. Вызвать `renga_ui_snapshot` и **посмотреть полученный PNG**.
3. Взять `SnapshotId` из текстового блока этого ответа. Использовать только координаты этого PNG, без масштабирования.
4. Выполнить одно действие с `preview=false`. Следующий ввод требует токена из нового ответа и осмотра нового снимка.
5. Повторно прочитать объекты, геометрию и уровни, проверить итог на снимке. Не повторять Paste/Enter вслепую после неопределённого результата.

Токен действует 60 секунд, привязан к процессу, модели, виду и окну/диалогу. Изменение API-модели, выбора или вида аннулирует предшествующий токен. Перемещение/изменение размера окна требует нового снимка. Щелчки вне изображения и поверх посторонних окон отвергаются. При отказе Windows передать фокус нужно вывести Renga на передний план и повторить снимок. Уровень привилегий Renga и сервера должен быть совместимым с Windows SendInput; сервер не обходит UIPI.

Обычный `renga_get_screenshot` остаётся снимком **только модельного вида**, его пиксели нельзя передавать в `renga_ui_click`. UI-снимок содержит клиентскую область окна в физических пикселях, включая панели, но не системную рамку/заголовок. Снимок снимается с видимого экрана: перекрывающие окна могут попасть в изображение; сервер проверяет принадлежность цели щелчка процессу Renga. Во время ввода не следует параллельно работать с мышью/клавиатурой.

## Копирование объектов

Для объектов модели можно задать выбор через `renga_select_objects`, затем получить новый UI-снимок и убедиться, что выделены нужные объекты и фокус находится в модели. Отправить `renga_ui_key(key="copy", preview=false)`, затем после осмотра нового снимка — `key="paste"`. Штатная вставка может потребовать точку/хост и подтверждение. Указывать их по новым снимкам через `renga_ui_click` и `renga_ui_type_text`; завершить один экземпляр и выйти из повторяющегося построения через `escape` при необходимости.

Это штатное копирование Renga с её правилами сохранения геометрии, параметров, стилей и связей, а не реконструкция объектов по нескольким параметрам. Набор копируемых объектов и допустимость вставки определяет сама Renga. Копирование заменяет системный буфер обмена. `ClipboardSequenceNumber` позволяет заметить его обновление, но не доказывает корректность состава копии. Содержимое буфера сервер не читает и не публикует.

## Копирование целого уровня с содержимым

Надёжный документированный путь: открыть 3D-вид, выбрать обозначение нужного уровня, получить свежий UI-снимок и выполнить **Ctrl+щелчок по его ручке**:

```json
{"snapshotId":"TOKEN_FROM_UI_IMAGE","x":100,"y":100,"modifier":"ctrl","preview":false}
```

Значения `x/y` в примере — только иллюстрация формата, их нельзя использовать без осмотра реального снимка. Затем задать положение/расстояние в динамическом поле, подтвердить через Enter или точку и выйти из копирования. Вместе с уровнем Renga копирует расположенные на нём объекты. Проверить новый GUID уровня, отметку, количество и принадлежность копий объектов. Копирование миниатюры плана в обозревателе проекта не следует автоматически считать копированием уровня со всей моделью.

## Изменение высоты существующего уровня

В проверенной Renga Professional 9.2 / API 2.49 `ILevel.Elevation` и параметр `LevelElevation` доступны только для чтения. Вызов SetDoubleValue на read-only параметре может вернуться без ошибки и ничего не изменить. Модификация копии `ILevel.Placement` также не меняет уровень. Сервер не выдаёт такие вызовы за успешное изменение высоты и не удаляет/пересоздаёт уровень.

Для изменения отметки выбрать обозначение уровня в 3D-виде, нажать его **ручку без Ctrl**, затем задать новое положение в **динамическом поле ввода** и подтвердить. Это штатный способ Renga, а не запись read-only значения в панели параметров. По текущему виду поля определить, задана абсолютная отметка или расстояние. Для ввода использовать `renga_ui_type_text`; десятичный разделитель и единицы соответствуют интерфейсу. После подтверждения вызвать `renga_get_levels`: отметки там всегда в миллиметрах. Объекты уровня могут переместиться вместе с ним по правилам Renga.

## Перемещение

Для поддерживаемых API объектов использовать `renga_move_objects` с явным массивом GUID и `translationMm={"x":1000,"y":0,"z":3000}`. Это относительный сдвиг, не абсолютная координата. Оси размещения и базовые линии сохраняются. Повторный commit повторяет сдвиг, поэтому команда не идемпотентна.

Для окна, двери, хоста с зависимостями, уровня и других неподдерживаемых SetPlacement объектов использовать штатную команду `renga_ui_key(key="move")` или наблюдаемую ручку. Выполнить точное позиционирование через динамическое поле/точки и проверить геометрию/отметки после завершения.

## Проверка реализации

- 48 автоматических тестов, в том числе откат пакетного сдвига, отказ смешанного неподдерживаемого набора, безопасные значения по умолчанию, границы/срок токенов, ограничение клавиш и Unicode, декодирование и CRC PNG.
- Реальный stdio MCP: версия 0.4.0, 31 инструмент, preview по умолчанию; mock не изображает управление рабочим столом.
- На Renga Professional 9.2 / API 2.49: чтение семи уровней, пакетный сдвиг стены в preview с восстановлением, откат неподдерживаемого набора, PNG клиентской области с панелями, проверка UI-плана и отказ устаревшего токена.
- Настоящий Ctrl+C на выбранной стене обновил буфер Renga. Выбор восстановлен. Вставка, изменение уровня и commit сдвига на пользовательском проекте при проверке не выполнялись. Исходный набор объектов и отметки уровней сохранились. Весь интерактивный цикл копирования уровня/изменения высоты требует дополнительной проверки на целевом проекте.
